### テストケース

#### roundtrip.test.ts
```typescript
describe('ラウンドトリップテスト', () => {
  it('toXML → fromXML で内容が保持される', () => {
    // Arrange
    const manager = new FileManager();
    const originalFiles = [ ... ];
    originalFiles.forEach(f => manager.setFile(f));

    // Act
    const xml = RepomixAdapter.toXML(manager);
    const newManager = new FileManager();
    RepomixAdapter.fromXML(xml, newManager);

    // Assert
    originalFiles.forEach(original => {
      const restored = newManager.getFile(original.path);
      expect(restored?.content).toBe(original.content);
    });
  });

  it('特殊文字を含むファイルでラウンドトリップが成功する', () => {
    // HTMLタグ、&、"、'等を含むファイルのテスト
  });
});
```

## テストのベストプラクティス

### 1. AAA（Arrange-Act-Assert）パターン
```typescript
it('テストケース', () => {
  // Arrange: 準備
  const manager = new FileManager();

  // Act: 実行
  manager.setFile(file);

  // Assert: 検証
  expect(manager.getFile(file.path)).toBeDefined();
});
```

### 2. 1テスト1アサーション
各テストは1つの機能のみを検証する。

### 3. 意味のあるテスト名
```typescript
// ❌ 悪い例
it('test1', () => { ... });

// ✅ 良い例
it('新規ファイルを追加できる', () => { ... });
```

### 4. テストの独立性
各テストは他のテストに依存しない。

### 1. エラーメッセージを確認
```bash
npm test -- --reporter=verbose
```

### 2. 特定のテストのみ実行
```bash
npm test -- -t "新規ファイルを追加できる"
```

### 3. デバッグモード
```typescript
it.only('デバッグ対象のテスト', () => {
```
