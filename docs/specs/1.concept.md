# RepomixWebTool - コンセプト

## プロジェクト概要

**RepomixをWeb上で実行できるツール。かつ、RepomixでMixされたファイルをUnmixできるようにする。**

## 背景と目的

### 現状の課題
Web上のAIチャット（ChatGPT、Claude等）でソースコードを生成する際、以下の問題がある：

1. **手動ファイル作成の手間**: AIが生成したコードを手動でファイルに貼り付ける必要がある
2. **ディレクトリ構造の再現**: 複数ファイルの場合、ディレクトリ構造を手動で作成する必要がある
3. **コピー&ペーストの繰り返し**: ファイル数が多いと非常に時間がかかる
4. **ミスの発生**: 手動操作によるファイル配置ミスやコピーミスが発生しやすい

### 解決策
**Repomix形式を介した完全自動化**

```
従来のフロー:
AI生成 → 手動でファイル作成 → 手動でディレクトリ構築 → 手動でコピペ

新しいフロー:
AI生成（Repomix XML） → Unmixボタン → 完成！
```

## コアコンセプト

### 1. ブラウザ上でのローカルファイル操作
- **File System Access API**を使用してブラウザからローカルファイルシステムにアクセス
- 任意のフォルダを選択し、読み書き可能にする
- サーバー不要の完全クライアントサイド動作

### 2. Repomix形式の双方向変換
- **Mix機能**: ローカルフォルダ → Repomix XML形式
- **Unmix機能**: Repomix XML形式 → ローカルフォルダ

### 3. 安全な中間層アーキテクチャ
```
UI層
  ↕
FileManager（メモリ上のファイル保持）
  ↕                    ↕
RepomixAdapter    FileSystemAdapter
  ↕                    ↕
Repomix XML      実ファイルシステム
```

直接ファイルを操作せず、FileManagerを介することでセキュリティと柔軟性を確保。

## 主要機能

### Mix機能
1. ブラウザでローカルフォルダを開く
2. フォルダ内のファイルを読み込み
3. .gitignoreルールを適用してフィルタリング
4. Repomix XML形式に変換
5. Monaco Editorに表示

### Unmix機能
1. Repomix XML形式のテキストをMonaco Editorに貼り付け
2. XMLをパースしてファイル構造を解析
3. ローカルフォルダに自動展開（ディレクトリ自動作成）
4. 既存ファイルは無条件上書き

## 技術スタック

- **フロントエンド**: React.js + TypeScript
- **エディタ**: Monaco Editor（VS Codeと同じエンジン）
- **ファイルアクセス**: File System Access API
- **テスト**: Vitest + Testing Library
- **対象ブラウザ**: Chrome 86+ / Edge 86+（File System Access API対応）

## ユースケース

### ケース1: AIでプロジェクト生成
```
1. AIチャットで「Reactアプリを作って」と依頼
2. AIがRepomix XML形式でコード生成
3. XMLをコピーしてRepomixWebToolに貼り付け
4. Unmixボタンをクリック
5. 完全なプロジェクトがローカルに展開される
```

### ケース2: 既存プロジェクトのAI解析
```
1. ローカルプロジェクトのフォルダを開く
2. Mixボタンをクリック
3. 生成されたRepomix XMLをコピー
4. AIチャットに貼り付けて「このコードをレビューして」
5. AIが全体を理解してレビュー
```

### ケース3: コードの修正提案適用
```
1. 既存プロジェクトをMix → AIに送信
2. AIが修正版のRepomix XMLを生成
3. 修正版XMLをUnmix
4. 変更が自動的にローカルに反映される
```

## 価値提案

### 開発者にとって
- **時間節約**: 手動ファイル作成が完全に不要
- **エラー削減**: コピペミスやファイル配置ミスがゼロ
- **AI活用の最大化**: AIの生成結果をそのまま使える

### AIにとって
- **構造化された出力**: Repomix形式で明確な構造
- **完全な文脈**: プロジェクト全体を一度に理解可能
- **標準フォーマット**: yamadashy/repomixという実績ある形式

## 設計原則

1. **セキュリティ第一**: 直接ファイル操作を避け、中間層で検証
2. **ユーザー体験重視**: 最小限のクリックで完結
3. **完全な透明性**: すべての操作がMonaco Editorで確認可能
4. **拡張性**: 将来的な機能追加を見据えた設計
5. **テスタビリティ**: すべてのコア機能が単体テスト可能

## 制約と前提

### 技術的制約
- File System Access API対応ブラウザのみ（Chrome/Edge）
- テキストファイルのみ対応（バイナリファイルは除外）
- ユーザーの明示的な許可が必要

### 設計上の制約
- セキュリティ機能は最小限（ユーザー要求により）
- JSON形式は不要（XML形式のみ）
- エスケープ処理なし（yamadashy/repomix標準準拠）

## 成功の定義

1. **機能的成功**: Mix/Unmixが完璧に動作する
2. **互換性**: yamadashy/repomixおよびrepounmix CLIと完全互換
3. **ユーザビリティ**: 初めてのユーザーが直感的に使える
4. **信頼性**: ラウンドトリップテスト（mix → unmix → mix）で内容が完全保持される
