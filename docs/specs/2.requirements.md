# RepomixWebTool - 要件定義

## 機能要件

### FR-001: フォルダ選択機能
**優先度**: 高

**説明**: ユーザーがブラウザからローカルフォルダを選択できる

**詳細要件**:
- File System Access APIの`showDirectoryPicker()`を使用
- 読み書き権限を要求（`mode: 'readwrite'`）
- 権限が拒否された場合はエラーメッセージ表示
- 選択したフォルダのパスを表示

**受け入れ基準**:
- フォルダ選択ダイアログが表示される
- 権限が付与されるとフォルダ内容が読み込まれる
- 権限失効時に再要求できる

---

### FR-002: ファイルツリー表示
**優先度**: 高

**説明**: 選択したフォルダの構造をツリー形式で表示

**詳細要件**:
- ディレクトリとファイルを区別して表示
- 階層構造を視覚的に表現
- ファイルクリックで内容を表示
- .gitignoreで除外されたファイルは表示しない（将来実装）

**受け入れ基準**:
- フォルダ構造が正しく表示される
- ファイルをクリックするとエディタに内容が表示される
- 大量ファイルでもパフォーマンスが維持される

---

### FR-003: Mix機能（ローカル → Repomix XML）
**優先度**: 最高

**説明**: ローカルフォルダをRepomix XML形式に変換

**詳細要件**:
- すべてのテキストファイルを読み込み
- yamadashy/repomix標準XML形式で出力
- エスケープ処理なし（Repomix標準準拠）
- ディレクトリ構造セクションを含む
- file_summaryセクションを含む

**XML形式**:
```xml
<file_summary>...</file_summary>
<directory_structure>...</directory_structure>
<files>
<file path="...">
内容（エスケープなし）
</file>
</files>
```

**受け入れ基準**:
- 生成されたXMLがyamadashy/repomixの出力と同じ形式
- すべてのファイル内容が正確に含まれる
- 特殊文字（`<`, `>`, `&`等）がそのまま保持される
- repounmix CLIで正しくUnmixできる

---

### FR-004: Unmix機能（Repomix XML → ローカル）
**優先度**: 最高

**説明**: Repomix XMLをローカルフォルダに展開

**詳細要件**:
- XMLをパースしてファイル構造を復元
- ディレクトリを自動作成
- 既存ファイルは無条件上書き
- パース失敗時は詳細エラー表示

**受け入れ基準**:
- XMLから正確にファイルが復元される
- ディレクトリ構造が正しく再現される
- 既存ファイルが上書きされる
- 特殊文字が正しく復元される

---

### FR-005: Monaco Editor統合
**優先度**: 高

**説明**: 2つのタブでファイル編集とRepomix XML表示

**詳細要件**:
- **File Editorタブ**: 選択したファイルの表示・編集
- **Repomix XMLタブ**: Mix結果表示・Unmix用XML編集
- シンタックスハイライト対応
- 自動保存機能（File Editorタブ）

**タブ切り替え動作**:
- ツリーでファイル選択 → File Editorタブに自動切り替え
- Mixボタンクリック → Repomix XMLタブに自動切り替え

**受け入れ基準**:
- タブ切り替えがスムーズ
- シンタックスハイライトが正しく動作
- 編集内容が自動保存される（500msデバウンス）

---

### FR-006: 自動保存機能
**優先度**: 中

**説明**: File Editorタブでの編集を自動保存

**詳細要件**:
- 編集後500ms経過で自動保存
- 保存状態を表示（保存中/保存済み/未保存）
- FileManagerを経由してローカルファイルに書き込み

**受け入れ基準**:
- タイピング中は保存されない
- 500ms経過後に自動保存される
- 保存状態が視覚的に確認できる

---

### FR-007: フォルダ同期機能
**優先度**: 低（将来実装）

**説明**: 外部でのファイル変更を検出して反映

**詳細要件**:
- 3秒間隔でポーリング
- 変更されたファイルを検出
- 自分の変更は除外
- 競合時はユーザーに確認

**受け入れ基準**:
- 外部変更が自動的に反映される
- 自分の変更と区別できる
- パフォーマンスに影響しない

---

## 非機能要件

### NFR-001: パフォーマンス
- **ファイル読み込み**: 1000ファイルを5秒以内
- **Mix処理**: 10MBのコードベースを3秒以内
- **Unmix処理**: 100ファイルを2秒以内
- **UI応答性**: すべての操作が100ms以内に反応

### NFR-002: 互換性
- **yamadashy/repomix**: 完全互換
- **repounmix CLI**: 完全互換
- **ラウンドトリップ**: mix → unmix → mixで内容が完全保持

### NFR-003: ユーザビリティ
- **学習曲線**: 初めてのユーザーが5分以内に使いこなせる
- **エラーメッセージ**: すべてのエラーが明確で対処法が示される
- **フィードバック**: すべての操作に視覚的フィードバック

### NFR-004: 保守性
- **コードカバレッジ**: コア機能80%以上
- **ドキュメント**: すべての関数にJSDoc
- **型安全性**: TypeScriptで完全な型定義

### NFR-005: セキュリティ
- **パスサニタイズ**: `../`等の不正パス防止
- **ルート外アクセス**: 選択フォルダ外への書き込み禁止
- **権限管理**: File System Access APIの権限モデルに準拠

---

## 制約条件

### 技術的制約
1. **ブラウザ対応**: Chrome 86+、Edge 86+のみ
2. **ファイル形式**: テキストファイルのみ（バイナリ除外）
3. **出力形式**: XML形式のみ（JSON不要）
4. **エスケープ**: なし（Repomix標準準拠）

### ユーザー要求による制約
1. **セキュリティ**: 最小限の実装（Secretlint等は不要）
2. **上書き**: 既存ファイルは無条件上書き
3. **JSON**: 不要
