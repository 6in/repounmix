### 2. Core Layer（ビジネスロジック層）

**責務**: ファイル管理、変換処理、ビジネスロジック

#### FileManager（中核クラス）

**役割**: メモリ上でファイルを管理し、実ファイルへの直接操作を避ける

**設計理念**:
- 直接ファイル操作の危険性を排除
- 変更追跡による安全性確保
- undo/redo実装の基盤

**主要メソッド**:
```typescript
class FileManager {
  // ファイル保持
  private files: Map<string, FileNode>;
  
  // ファイル追加・更新（自動ステータス判定）
  setFile(fileNode: FileNode): void
  
  // ファイル取得
  getFile(path: string): FileNode | undefined
  
  // すべてのファイル取得
  getAllFiles(): FileNode[]
  
  // 変更されたファイルのみ取得
  getModifiedFiles(): FileNode[]
  
  // ディレクトリツリー構築
  buildTree(): DirectoryNode
}
```

**データ構造**:
```typescript
interface FileNode {
  path: string;              // 相対パス
  absolutePath?: string;     // 絶対パス
  mimeType: string;          // MIMEタイプ
  content: string;           // ファイル内容
  metadata: FileMetadata;    // メタデータ
  status: FileStatus;        // 変更状態
}

type FileStatus = 'unchanged' | 'modified' | 'added' | 'deleted';
```

#### RepomixAdapter（変換アダプター）

**役割**: FileManager ↔ Repomix XML の双方向変換

**設計理念**:
- yamadashy/repomix完全互換
- エスケープなし（標準準拠）
- 正規表現ベースのシンプルなパーサー

**主要メソッド**:
```typescript
class RepomixAdapter {
  // FileManager → Repomix XML
  static toXML(manager: FileManager): string
  
  // Repomix XML → FileManager
  static fromXML(xml: string, manager: FileManager): void
  
  // XML解析（内部）
  private static parseRepomixXML(xml: string): RepomixFileData[]
  
  // MIMEタイプ検出（内部）
  private static detectMimeType(path: string): string
}
```

**XML形式**:
```xml
<file_summary>...</file_summary>
<directory_structure>...</directory_structure>
<files>
<file path="相対パス">
内容（エスケープなし）
</file>
</files>
```

**重要な設計決定**:
- **エスケープなし**: yamadashy/repomixに準拠
- **正規表現パーサー**: 軽量で高速
- **文字列連結**: テンプレートリテラルの問題を回避

---

#### FileSystemAdapter（ファイルシステムアダプター）

**役割**: FileManager ↔ 実ファイルシステム の双方向変換

**設計理念**:
- File System Access API完全活用
- 権限管理の適切な処理
- エラーハンドリングの充実

**主要メソッド**:
```typescript
class FileSystemAdapter {
  // フォルダ選択
  async selectFolder(): Promise<FileSystemDirectoryHandle>
  
  // 実ファイル → FileManager
  async loadToManager(
    manager: FileManager,
    handle: FileSystemDirectoryHandle,
    rootPath: string
  ): Promise<void>
  
  // FileManager → 実ファイル
  async saveFromManager(manager: FileManager): Promise<void>
  
  // 権限確認・要求（内部）
  private async verifyPermission(
    handle: FileSystemDirectoryHandle,
    readWrite: boolean
  ): Promise<boolean>
}
```

**処理フロー**:
```
loadToManager:
1. ディレクトリを再帰的にスキャン
2. テキストファイルのみ読み込み
3. FileNodeを作成してFileManagerに追加
4. status = 'unchanged'

saveFromManager:
1. FileManager.getAllFiles()を取得
2. status別に処理:
   - 'added' / 'modified' → 書き込み
   - 'deleted' → 削除
   - 'unchanged' → スキップ
3. 処理後、すべてのstatusを'unchanged'に変更
```

#### RepomixCore（統合サービス）

**役割**: すべてのコア機能を統合して提供

**設計理念**:
- シンプルなAPI
- UIから直接使いやすい
- エラーハンドリングの集約

**主要メソッド**:
```typescript
class RepomixCore {
  private fileManager: FileManager;
  private fileSystemAdapter: FileSystemAdapter;
  
  // フォルダを開く
  async openFolder(): Promise<void>
  
  // Mix: FileManager → Repomix XML
  mix(): string
  
  // Unmix: Repomix XML → FileManager → 実ファイル
  async unmix(xml: string): Promise<void>
  
  // FileManager取得（UI用）
  getFileManager(): FileManager
  
  // 状態クリア
  clear(): void
}
```

## データフロー

### Mix処理のデータフロー
```
1. UI: "Mixボタン"クリック
   ↓
2. RepomixCore.mix()呼び出し
   ↓
3. FileManager.getAllFiles()でファイル取得
   ↓
4. RepomixAdapter.toXML()でXML生成
   ↓
5. UI: Repomix XMLタブに表示
```

### Unmix処理のデータフロー
```
1. UI: Repomix XMLタブにXML貼り付け
   ↓
2. UI: "Unmixボタン"クリック
   ↓
3. RepomixCore.unmix(xml)呼び出し
   ↓
4. RepomixAdapter.fromXML()でFileManagerに読み込み
   ↓
5. FileSystemAdapter.saveFromManager()で実ファイルに保存
   ↓
6. UI: フォルダツリー更新
```

### ファイル編集のデータフロー
```
1. UI: FileTreeでファイルクリック
   ↓
2. FileManager.getFile(path)で内容取得
   ↓
3. UI: File Editorタブに表示
   ↓
4. ユーザー: 編集
   ↓
5. 500msデバウンス後
   ↓
6. FileManager.setFile()で更新（status = 'modified'）
   ↓
7. FileSystemAdapter.saveFromManager()で保存
   ↓
8. FileManager: status = 'unchanged'に変更
```

## 設計パターン

### 1. Adapter Pattern
- RepomixAdapter: FileManager ↔ Repomix XML
- FileSystemAdapter: FileManager ↔ 実ファイルシステム

### 2. Facade Pattern
- RepomixCore: すべてのコア機能への統一インターフェース

### 3. Repository Pattern
- FileManager: ファイルデータのリポジトリ

### 4. Strategy Pattern（将来）
- 異なるフォーマット対応（JSON等）

## エラーハンドリング戦略

### 1. 権限エラー
```typescript
try {
  await fileSystemAdapter.selectFolder();
} catch (error) {
  if (error.name === 'NotAllowedError') {
    // 権限拒否時の処理
    showError('フォルダへのアクセスが拒否されました');
  }
}
```

### 2. XML解析エラー
```typescript
try {
  RepomixAdapter.fromXML(xml, manager);
} catch (error) {
  showError('XMLの解析に失敗しました: ' + error.message);
}
```

### 3. ファイル書き込みエラー
```typescript
try {
  await fileSystemAdapter.saveFromManager(manager);
} catch (error) {
  showError('ファイルの保存に失敗しました: ' + error.message);
}
```

## パフォーマンス最適化

### 1. 非同期処理
- ファイル読み込み: `Promise.all()`で並列化
- ディレクトリスキャン: `for await...of`で逐次処理

### 2. メモリ管理
- 大容量ファイルの警告（5MB以上）
- バイナリファイルの除外

### 3. UI応答性
- 自動保存のデバウンス（500ms）
- フォルダ同期のポーリング間隔（3秒）

## セキュリティ考慮事項

### 1. パスサニタイズ
```typescript
function sanitizePath(path: string): string {
  // ../ を含むパスを拒否
  if (path.includes('../') || path.includes('..\\')) {
    throw new Error('Invalid path');
  }
  return path;
}
```

### 2. ルート外アクセス防止
- 選択したフォルダ外への書き込みを禁止
- File System Access APIの制約に依存

### 3. 権限管理
- 読み取り専用 vs 読み書き権限の明確な区別
- 権限失効時の再要求フロー
