# RepomixWebTool - 技術的決定事項

## 重要な技術的決定とその理由

### 1. エスケープ処理なし（Repomix標準準拠）

**決定**: Repomix XMLでHTMLタグ等をエスケープしない

**理由**:
- yamadashy/repomixの標準動作に準拠
- 実際のテストで動作確認済み
- repounmix CLIとの完全互換性

**影響**:
- XMLパーサーは寛容なモードで動作
- 厳密なXMLバリデーションは行わない
- 正規表現ベースのシンプルなパーサーで十分

**代替案を却下した理由**:
- エスケープありの場合、yamadashy/repomixと互換性がなくなる
- 既存のrepounmix CLIで処理できなくなる

---

### 2. 文字列連結によるXML生成

**決定**: テンプレートリテラルではなく文字列連結を使用

**理由**:
- テンプレートリテラルは複数行で問題が発生
- Repomix/Repounmixのラウンドトリップで壊れる
- 文字列連結は確実で安全

**実装例**:
```typescript
// ❌ 問題のあるコード
xml += `&lt;file path="${path}">\n`;

// ✅ 正しいコード
xml += '&lt;file path="' + path + '">\n';
```

---

### 3. FileManagerによる中間層

**決定**: 直接ファイル操作を避け、FileManagerを介する

**理由**:
- **セキュリティ**: 書き込み前の検証が可能
- **テスタビリティ**: ファイルシステムなしでテスト可能
- **柔軟性**: undo/redo等の機能追加が容易
- **状態管理**: 変更追跡が簡単

**アーキテクチャ**:
```
UI → FileManager → Adapter → 実ファイル
```

---

### 4. React + TypeScript

**決定**: React.js + TypeScriptで実装

**理由**:
- **型安全性**: TypeScriptによる堅牢な実装
- **コンポーネント**: UIの再利用性が高い
- **エコシステム**: 豊富なライブラリ
- **学習コスト**: 広く使われている技術

**代替案**:
- Vue.js: Reactと同等だが、エコシステムが小さい
- Svelte: パフォーマンスは良いが、エコシステムが未成熟

---

### 5. Monaco Editor

**決定**: Monaco Editorをエディタとして採用

**理由**:
- **VS Codeと同じエンジン**: 高機能で信頼性が高い
- **シンタックスハイライト**: 多言語対応
- **React統合**: `@monaco-editor/react`で簡単に統合
- **カスタマイズ性**: 豊富な設定オプション

**代替案**:
- CodeMirror: 軽量だが機能が少ない
- Ace Editor: 古い、メンテナンスが不活発

---

### 6. Vitest

**決定**: Vitestをテストフレームワークとして採用

**理由**:
- **Viteとの統合**: 設定が簡単
- **高速**: Viteの高速ビルドを活用
- **Jest互換**: 既存のJest知識が使える
- **ESM対応**: モダンなJavaScript対応

**代替案**:
- Jest: 設定が複雑、ESM対応が不完全
- Mocha: 機能が少ない

---

### 7. File System Access API

**決定**: File System Access APIでローカルファイルにアクセス

**理由**:
- **ブラウザ標準API**: サーバー不要
- **直接ファイル操作**: ダウンロード不要
- **権限管理**: セキュアな実装

**制約**:
- Chrome/Edgeのみ対応
- HTTPSまたはlocalhost必須
- ユーザーの明示的な許可が必要

**代替案**:
- File API + Blob Download: 読み取りのみ、ダウンロードが必要
- Electron: デスクトップアプリ化が必要

---
