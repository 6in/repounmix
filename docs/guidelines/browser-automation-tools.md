# ブラウザ自動化ツール選択ガイドライン

## 目的
ブラウザ自動化が必要なタスクにおいて、適切なツール・MCPを選択し、効率的に開発を進めるためのガイドライン。

---

## ツール比較

### Playwright MCP

**特徴:**
- テスト自動化に特化
- ファイル選択ダイアログを自動インターセプト
- 豊富なAPI（スクリーンショット、ネットワーク監視など）
- マルチブラウザ対応

**適している用途:**
- ✅ 完全自動化されたE2Eテスト
- ✅ CI/CDパイプラインでのテスト
- ✅ スクリーンショット比較テスト
- ✅ ネットワークリクエストの監視・モック

**適していない用途:**
- ❌ 手動操作とMCP操作の混在
- ❌ ファイル選択ダイアログの手動テスト
- ❌ 開発中のインタラクティブなデバッグ

**制約:**
- `Page.setInterceptFileChooserDialog()`が常に有効
- ファイル選択には`browser_file_upload`ツールが必要
- 手動クリックでダイアログを開くことは不可能

---

### Chrome DevTools MCP

**特徴:**
- Chrome DevTools Protocolベース
- 手動操作とMCP操作の併用が可能
- 軽量・シンプル
- Chromeのみサポート

**適している用途:**
- ✅ 開発中のインタラクティブなテスト
- ✅ 手動操作の確認
- ✅ デバッグ作業
- ✅ ファイル選択ダイアログの手動テスト

**適していない用途:**
- ❌ 複雑な自動化シナリオ
- ❌ クロスブラウザテスト
- ❌ 高度なネットワーク操作

**制約:**
- Chrome/Chromiumのみ
- Playwrightより機能が限定的

---

### 通常のブラウザ（手動操作）

**特徴:**
- 実際のユーザー体験を再現
- 全機能が正常に動作
- デバッグツールが使える

**適している用途:**
- ✅ 最終的な動作確認
- ✅ UIのビジュアル確認
- ✅ ブラウザ互換性テスト
- ✅ パフォーマンステスト

**適していない用途:**
- ❌ 自動化が必要なテスト
- ❌ 繰り返し実行するテスト

## 実装パターン

### Pattern 1: 完全自動化テスト（Playwright MCP）

```typescript
// テストコード内でファイルアップロード
await page.locator('input[type="file"]').setInputFiles([
  '/path/to/file1.txt',
  '/path/to/file2.txt'
]);
```

**メリット:**
- 繰り返し実行可能
- CI/CDで自動化

**デメリット:**
- 手動操作不可
- セットアップが複雑

---

### Pattern 2: 開発中のテスト（Chrome DevTools MCP）

```javascript
// MCPでページを開く
mcp_chrome-devtoo_new_page("http://localhost:5173")

// 手動でボタンをクリック → ダイアログが開く
// ユーザーが手動でフォルダを選択

// MCPでスナップショットを取得して確認
mcp_chrome-devtoo_take_snapshot()
```

**メリット:**
- 実際のUI動作を確認
- 柔軟なテスト

**デメリット:**
- 完全自動化は不可
- 手動操作が必要

---

### Pattern 3: 最終確認（通常のブラウザ）

```bash
# 開発サーバー起動
npm run dev

# ブラウザで開く
open http://localhost:5173
```

**メリット:**
- 実際のユーザー体験
- 全機能が動作

**デメリット:**
- 自動化不可
- 繰り返しテストが面倒

## トラブルシューティング

### 問題: ファイル選択ダイアログが開かない

**確認事項:**
1. 使用しているMCPは何か？
   - Playwright MCP → 正常動作（自動インターセプト）
   - Chrome DevTools MCP → 手動操作可能
   - 通常のブラウザ → 手動操作可能

2. `showDirectoryPicker()` の呼び出し方法は正しいか？
   - ユーザーアクション起点で呼び出す必要がある
   - トップレベルのイベントハンドラー内で呼び出す

3. ブラウザのコンソールにエラーは出ていないか？
   - 権限エラー
   - セキュリティエラー

**解決策:**
- Playwright MCP使用時 → `browser_file_upload`ツールを使用
- Chrome DevTools MCP使用時 → 手動でダイアログを操作
- それでもダメ → 通常のブラウザで確認

---

### 問題: コード変更が反映されない

**確認事項:**
1. 開発サーバーは再起動したか？
2. ブラウザはリロードしたか？（ハードリロード推奨）
3. ブラウザキャッシュをクリアしたか？

**解決策:**
```bash
# 開発サーバー再起動
npm run dev

# ブラウザで Cmd+Shift+R（macOS）または Ctrl+Shift+R（Windows）
```

## ベストプラクティス

### 1. 開発初期段階
**使用ツール**: Chrome DevTools MCP または 通常のブラウザ
- 手動で機能を確認
- UIの動作を検証
- デバッグしやすい

### 2. 機能実装完了後
**使用ツール**: Playwright MCP
- 自動化テストを実装
- リグレッションテストを作成
- CI/CDに組み込む

### 3. 本番デプロイ前
**使用ツール**: 通常のブラウザ（複数）
- クロスブラウザテスト
- 実際のユーザー体験を確認
- パフォーマンステスト
